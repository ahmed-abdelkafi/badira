# Production deployment — Cloudflare

Everything runs on Cloudflare: the Next.js app (public site + admin + API) on **Workers** via the OpenNext adapter, the database on **D1**, photos on **R2**, image resizing with **Cloudflare Images**.

```
Browser ──► Worker "la-badira" (Next.js via @opennextjs/cloudflare)
              ├─ D1  "la-badira"         (binding DB)     — all data
              ├─ R2  "la-badira-media"   (binding MEDIA)  — uploaded photos
              └─ Images                  (binding IMAGES) — AVIF/WebP resizing, upload normalisation
```

## 0. Plan & costs — 100 % free

Designed for **Cloudflare's free plans**:

| Service | Free allowance | This site |
|---|---|---|
| Workers Free | 100 000 requests/day, **10 ms CPU per request** | Password hashing runs in the browser (PBKDF2) so login fits the CPU budget; Worker ≈ 2.1 MiB |
| D1 | 5 M rows read/day, 100 k rows written/day, 5 GB | Far above a hotel's traffic |
| R2 | 10 GB storage, 1 M writes, 10 M reads / month, free egress | Photos |
| Images | 5 000 unique transformations / month | Fixed list of sizes, cached; if ever exceeded, the original photo is served (no charge on the Free plan) |

- **No email at all** — the hotel answers guests on **WhatsApp** (click-to-chat from each reservation). Admin password resets use a one-time link generated by an owner.
- Enabling R2 may ask for a payment method even though usage stays free (Cloudflare's docs are not explicit). Nothing is billed within the free allowance.
- Watch *Workers → la-badira → Metrics → CPU time*. Server-rendering heavy pages can occasionally exceed 10 ms; Cloudflare tolerates infrequent overruns. If errors 1102 appear regularly, the Workers Paid plan (5 USD/month) removes the limit — no code change needed.

## 1. One-time setup (≈ 15 minutes)

Run from the project folder. **Build and deploy from Linux or macOS** (WSL, GitHub Actions or Cloudflare Workers Builds) — OpenNext warns that Windows builds can fail unpredictably.

```bash
npm ci
npx wrangler login                                   # opens the browser — you log in yourself

# Database
npx wrangler d1 create la-badira                     # copy the "database_id" into wrangler.jsonc
# Photos
npx wrangler r2 bucket create la-badira-media
# Images: enable "Images" in the Cloudflare dashboard (Images → Overview) if not yet active.
```

Edit `wrangler.jsonc`:
- `d1_databases[0].database_id` ← the id printed above
- `vars.SITE_URL` ← your public URL (e.g. `https://www.labadira.com`)

Secrets (never in files):

```bash
# .prod.vars / .prod.secrets.json (gitignored) hold TOTP_ENCRYPTION_KEY + VAPID keys
npx wrangler secret bulk .prod.secrets.json
```

`NEXT_PUBLIC_VAPID_PUBLIC_KEY` is needed **at build time**: put it in `.env` (it is public) or in your CI environment.

> **Back up `TOTP_ENCRYPTION_KEY`** in the hotel's password manager. Losing or changing it invalidates every authenticator enrolment (owners would have to reset everyone's 2FA).

## 2. Database & content

```bash
npm run db:migrate:remote                            # applies drizzle/*.sql to D1
npm run db:seed -- --remote                          # verified content + photos → D1 + R2 (only if empty)
ADMIN_PASSWORD='…' npm run admin:create -- --email <owner email> --name "…" --role owner --remote   # reads the key from .prod.vars
```

## 3. Deploy

```bash
npm run deploy        # opennextjs-cloudflare build && deploy
```

Then attach the custom domain: Cloudflare dashboard → Workers & Pages → la-badira → Settings → Domains & Routes → add `www.labadira.com` (the domain must be on Cloudflare DNS). Update `SITE_URL` accordingly.

Health check: `GET /api/health` → `{"status":"ok"}`.

**Subsequent releases:** `npm run db:migrate:remote` (if the schema changed) then `npm run deploy`. For automatic deploys, connect the Git repository in *Workers Builds* with build command `npx opennextjs-cloudflare build` and deploy command `npx opennextjs-cloudflare deploy`.

## 7. Notes & limits

- Public pages render on each request from D1 (no page cache), so admin edits are visible immediately. Photos and static files are cached at the edge.
- Next.js "Cache Components" are intentionally **disabled**: OpenNext does not fully support them yet. Revisit when opennextjs-cloudflare PR #1318 lands.
- `middleware.ts` (edge) is used instead of Next 16's `proxy.ts`, whose Node runtime is only experimental on Cloudflare.
- Server Actions accept up to 50 MB per request (multiple photo uploads); each photo is limited to 15 MB.
- Admin passwords: the browser derives a PBKDF2-SHA256 proof (600 000 iterations, salt = email); the server stores HMAC-SHA256(secret, proof). The plain password never reaches the server.
